# Telegram-парсер строительных заявок

Сервис читает только группы и каналы, доступные подключённому Telegram-аккаунту.
Он не отправляет сообщения в рабочие чаты и не ищет скрытые персональные данные.

## Что извлекается

- товар или услуга;
- объём: м³, тонны, штуки, рейсы, машины, мешки, паллеты;
- телефон, email и открытый Telegram username;
- адрес или место выгрузки;
- название чата, автор, исходный текст и ссылка на сообщение;
- защита от повторного сохранения одного сообщения.

## Переменные окружения

- `TG_API_ID` и `TG_API_HASH` — создаются на `my.telegram.org`;
- `TG_USER_SESSION` — строковая сессия личного аккаунта;
- `TG_BOT_TOKEN` — токен бота от BotFather;
- `TG_OWNER_IDS` — Telegram ID владельцев через запятую;
- `TG_CHAT_ALLOWLIST` — необязательный список ID/username разрешённых чатов;
- `TG_CHAT_BLOCKLIST` — необязательный список исключённых чатов;
- `TG_HISTORY_LIMIT` — сообщений истории на один чат, по умолчанию `100`;
- `TG_BACKFILL` — `1` для первичного разбора истории, затем лучше поставить `0`;
- `TG_DB_PATH` — путь к SQLite, по умолчанию `telegram_leads.db`.

## Первый запуск

1. Установить зависимости из `requirements.txt`.
2. Задать `TG_API_ID` и `TG_API_HASH`.
3. Один раз запустить `python telegram_session_setup.py`.
4. Скопировать выданную строку в секрет `TG_USER_SESSION`.
5. Запустить `python telegram_lead_parser.py`.

На Render парсер должен работать отдельным Background Worker. Для сохранности
SQLite между перезапусками требуется постоянный диск; альтернативой будет
выгрузка заявок в Google Sheets/PostgreSQL на следующем этапе.
